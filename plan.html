The System

// how the data moves

One new system at the center, connected to the tools SPARC already works in. Arrows show which way data flows. The moving dots trace it in real time.

  • ⇄
    System ⇄ Google Sheets Backend

    Google Sheets is the system's backend: it's where the system's data lives, and data moves both ways between them.

  • →
    Banner → Argos Email → System

    A handoff import, not a direct one. Banner data comes over in an Argos email and is handed off into the system.

  • →
    Banner → BAR Report

    The Budget Availability Report is an existing SPARC tool, and it already pulls its data from Banner.

  • System — BAR Report

    Linked. Because BAR already reads from Banner, the new system links to it.

  • ⇄
    System ⇄ Google Drive

    Two-way. Data moves in both directions. SPARC works in the Google ecosystem, so the drive on the whiteboard is Google Drive.

  • ⇄
    System ⇄ DocuSign Routing

    Automatic. The system routes items through DocuSign on its own.

  • →
    System → Calendar

    One-way. The system puts an action item summary on the calendar.

The Teams

// two workstreams, one build

The build splits into two workstreams: what people see and touch, and the machinery underneath that keeps the data straight.

Product Design

Workstream A
Lead

Josi+Santhosh+Jane

Core idea

Make it a joy to use.

This team owns what the system looks like and how people move through it. The goal is an interface with real personality: polished, friendly, and colorful enough that working with SPARC data feels inviting instead of like a chore.

System Infrastructure

Workstream B
Lead

Owen+Dohyeon

Core idea

Make the data dependable.

This team owns the machinery underneath: how data gets into the system, how it's kept in order, and how it comes back out the moment someone needs it. Every screen the design team builds stands on this.
