Grant Statuses

// every place a grant can land

Every grant in the system carries one of these statuses. Most grants move forward along the main path, but four statuses are dead ends where a grant stops. The red dashed line marks where Pre-Award ends and Post-Award begins.

Main path Dead end Final status Pre-Award ends · Post-Award begins

Pre-Award

Stages 01–04
Main path
In Development→Submitted
Dead ends
CancelledDeniedDormantWithdrawn

A grant can be cancelled while it's still in development. Once it's submitted, it can be denied, go dormant, or be withdrawn, or it can be selected and move into Post-Award.

Post-Award

Stages 05–10
Main path
Selected→Awarded→In Closeout→Completed
Dead ends
None

Post-Award starts at Selected, which matches the grant life cycle, where Post-Award begins with the Notice of Award. From there, a grant moves straight through to Completed.

The Teams

// two workstreams, one build

The build splits into two workstreams: what people see and touch, and the machinery underneath that keeps the data straight.

Product Design

Workstream A
Lead

Josi+Santhosh+Jane

Core idea

Make it a joy to use.

This team owns what the system looks like and how people move through it. The goal is an interface with real personality: polished, friendly, and colorful enough that working with SPARC data feels inviting instead of like a chore.

System Infrastructure

Workstream B
Lead

Owen+Dohyeon

Core idea

Make the data dependable.

This team owns the machinery underneath: how data gets into the system, how it's kept in order, and how it comes back out the moment someone needs it. Every screen the design team builds stands on this.
