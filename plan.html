The System

One new system, fed from Banner through an Argos email handoff, backed by Google Sheets, and organized into five modules. Arrows show which way data flows. The moving dots trace it in real time.

  • ⇄
    System ⇄ Google Sheets Backend

    Google Sheets is the system's backend: it's where the system's data lives, and data moves both ways between them.

  • →
    Banner → Argos Email → System

    A handoff import, not a direct one. Banner data comes over in an Argos email and is handed off into the system.

  • Five modules inside the system

    Pre-Award and Post-Award follow the two phases of the grant life cycle, alongside Reporting, Forms and Calendar.

02

Grant Statuses

Every grant in the system carries one of these statuses. Most grants move forward along the main path, but six statuses are dead ends where a grant stops. The red dashed line marks where Pre-Award ends and Post-Award begins.

Main path Dead end Final status Pre-Award ends · Post-Award begins

Pre-Award

Stages 01–04
Main path
In Development→Submitted
Dead ends
CancelledDeniedDormantWithdrawn

A grant can be cancelled while it's still in development. Once it's submitted, it can be denied, go dormant, or be withdrawn, or it can be selected and move into Post-Award.

Post-Award

Stages 05–10
Main path
Selected→Awarded→In Closeout→Completed
Dead ends
DeclinedTerminated

Post-Award starts at Selected, which matches the grant life cycle, where Post-Award begins with the Notice of Award. A selected grant can still end as Declined, and an awarded grant can end as Terminated. Otherwise, it moves through to Completed.

Your next part

  1. Read your outline. It says exactly what your page shows and when it's done.
  2. Make a branch. Name it after the change, like pre-award-cards. Never work on main.
  3. Build in your folder. Only Page.html and Server.js, using the frame's pieces. Need something in ui/ or core/? Ask Nathan.
  4. Try it in your copy. Push to your own copy of the app. Check light mode, dark mode and phone width.
  5. Open a pull request. Reviewers: Nathan and the next owner in the rotation.

You're done when everything under “Done when” in your outline is true. Not sure about something? Ask in your pull request. That's what reviews are for.

Using Claude Code? It reads CLAUDE.md on its own. Start with: “Build my page from my module's OUTLINE.md.”

How to set up your copy
  1. In the Apps Script project, open Overview and choose Make a copy.
  2. Put the copy's Script ID (Project Settings) in your local .clasp.json. Don't commit that change.
  3. Run setup() once in the copy, then clasp push.
  4. Open the copy's link from Deploy → Test deployments.
